Problem Statement Medium
LeetCode 150

You are given an array of strings tokens that represents an arithmetic expression in a Reverse Polish Notation. Evaluate the expression and return an integer that represents its value.
• Valid operators are '+', '-', '*', and '/'.
• Division between two integers always truncates toward zero.
• There will not be any division by zero, and all intermediate values fit in a 32-bit signed integer.

Example 1: Input: tokens = ["2","1","+","3","*"] → Output: 9 ((2 + 1) * 3 = 9)
Example 2: Input: tokens = ["4","13","5","/","+"] → Output: 6 (4 + (13 / 5) = 6)
Example 3: Input: tokens = ["10","6","9","3","+","-11","*","/","*","17","+","5","+"] → Output: 22
Constraints: 1 ≤ tokens.length ≤ 104, tokens[i] is "+", "-", "*", "/" or an integer in [-200, 200].
Algorithm Summary & Operand Pop Order
O(N) Time • O(N) Space
Why second Is the Left Operand and first Is the Right Operand: In postfix notation A B - (meaning A - B), A is pushed first and B is pushed second on top of A. Therefore, the first stack.pop() retrieves first = B (right operand), and the second stack.pop() retrieves second = A (left operand) — making second - first and second / first exact!
Truncation Toward Zero & No Parentheses Needed: Reverse Polish Notation eliminates operator precedence ambiguity and parentheses because every operator immediately consumes the two most recent values on the stack and pushes its intermediate result back onto stack. Java's / operator natively truncates toward zero (e.g., 6 / -132 = 0).
