Problem Statement Easy / Medium
146 • LeetCode 88

Given two integer arrays nums1 and nums2, both sorted in non-decreasing order, merge both arrays into a single array sorted in non-decreasing order:
• The final sorted array must be stored inside nums1 in-place.
• nums1 has length m + n, where the first m elements denote the elements of nums1 and the rest are 0s.
• nums2 has length n.

Example 1:
Input: nums1 = [-5, -2, 4, 5, 0, 0, 0], nums2 = [-3, 1, 8]
Output: [-5, -3, -2, 1, 4, 5, 8]
Example 2:
Input: nums1 = [0, 2, 7, 8, 0, 0, 0], nums2 = [-7, -3, -1]
Output: [-7, -3, -1, 0, 2, 7, 8]
Practice Check:
Input: nums1 = [1, 3, 5, 0, 0, 0, 0], nums2 = [2, 4, 6, 7] → Output: [1, 2, 3, 4, 5, 6, 7]
Constraints: n == nums2.length, m + n == nums1.length, 0 ≤ n, m ≤ 1000, -104 ≤ nums1[i], nums2[i] ≤ 104.
Algorithm Summary & Reverse-Fill Proof
O(1) Aux Space
Why Merge From Back to Front (k = m + n - 1)? Merging left-to-right inside nums1 would overwrite unread elements of nums1 unless we allocate an Ο(m) temporary array. Because the trailing n slots of nums1 are empty buffer zeros, filling largest-to-smallest from k = m + n - 1 guarantees k > i always holds — so no unread element in nums1 is ever overwritten!
Why Only while (j >= 0) Cleanup Is Needed: If nums2 finishes first (j < 0), any remaining elements nums1[0..i] are already in their exact final sorted positions inside nums1. Only leftover elements in nums2 (j ≥ 0) need to be copied into nums1[0..k].
Time Complexity
Ο(M + N)

Each of the m + n elements is placed exactly once.

Space Complexity
Ο(1)

Purely in-place using only three integer pointers (i, j, k).
