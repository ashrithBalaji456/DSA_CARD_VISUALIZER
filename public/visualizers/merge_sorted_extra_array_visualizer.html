Problem Statement

Easy / Two Pointers
Merge Sort Subroutine • Extra Array

Given two sorted integer arrays a[] of length m and b[] of length n, combine all elements into a new sorted array merged[] of size m + n and print the merged sequence.

📌Key Properties & How It Compares
  • • Simplest & Fastest Linear Merge: Runs in clean O(m + n) time and forms the core merge step of Merge Sort.
  • • Not In-Place: Allocates an extra array int[] merged = new int[m + n], using O(m + n) auxiliary space (unlike LeetCode 88 or the Gap Method).
  • • Stable Ordering: Using a[i] <= b[j] preserves the relative order of equal elements (a[] elements come before equal b[] elements).
Input Format
Line 1: m n (array sizes)
Line 2: m sorted ints (a[])
Line 3: n sorted ints (b[])
Sample Output
Input: 3 3 / 1 4 7 / 2 3 6
Output: 1 2 3 4 6 7

Algorithm Summary & Complexity Analysis

O(m + n) Time • O(m + n) Space
🎯1. Why Use Two Pointers Instead of Concatenating & Sorting?

Copying both arrays into merged[] and calling Arrays.sort(merged) ignores the fact that a[] and b[] are already sorted, wasting O((m+n) log(m+n)) time. Because the next smallest element overall must always be at the front of either a[i] or b[j], comparing just those two front elements finishes in optimal O(m + n) linear time!

⚙️2. How the Three while Loops Work Step-by-Step:
  • Loop 1 (while (i < m && j < n)): Compare a[i] and b[j]. Copy the smaller value into merged[k++] and advance that array's pointer (i++ or j++).
  • Loop 2 (while (i < m)): Once b[] runs out, drain any remaining elements from a[] directly into merged[].
  • Loop 3 (while (j < n)): Conversely, if a[] ran out first, drain all remaining elements from b[] into merged[]. At most one of Loops 2 & 3 executes.
TIME COMPLEXITY
O(m + n)
Every element from a[] and b[] is visited and copied exactly once.
AUXILIARY SPACE
O(m + n)
Allocates the extra output array int[] merged = new int[m + n].
